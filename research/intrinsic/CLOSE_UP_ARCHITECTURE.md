# Close-up module — forward architecture (design before pages). 2026-06-12

**Purpose.** A "Close-up" is a *standardized investigation record* — a zoom into one structural question, showing
the full method and an honest verdict (including refutations). This doc fixes the schema so every future close-up
(Sūra, human-construct reindexings, new-instrument revisits) slots in without redesign, and so honesty is enforced
by STRUCTURE, not by narration.

**Journey line (where we are):** ledger cards (scoreboard) → graded ledger (two-tier, provisional) → **Close-up
group (the investigations / the story)**. This is the third view, and the one that carries method + journey.

## 1. Status vocabulary (LOCKED) — every close-up wears one badge
- **DEFINED** — a unit characterized to necessity (e.g. the Āyah).
- **CANDIDATE (grade)** — real, gated, climbing; not yet ≥90.
- **REDUCES-TO-KNOWN** — real signal that resolves to an existing ledger feature.
- **REFUTED-ARTIFACT** — survived early gates, killed by a later control (e.g. inter-Sūra = size artifact).
The badge is what stops a dense, pretty page from being misread as a discovery. Integrity in the frame.

## 2. Anatomy of every close-up (fixed schema)
1. **Question** (one line) + the unit/axis it targets.
2. **Status badge** + **grade** (links to GRADED_FINDINGS_LEDGER).
3. **Two-axis tags:** Substrate (ROOT / rasm-WORD / DIACRITIC-demote) · Arrangement (DIVINE-DEFAULT / DIVINE-ALT /
   HUMAN-CONSTRUCT / RANDOM-null).
4. **The gating cascade** — the signature chart: effect/z across each control, survive(green)/collapse(red),
   ending at the verdict. The fingerprint of the investigation.
5. **Instruments** used (named).
6. **Original-Arabic exhibit** — the actual data: roots / words / sūra-pairs in Arabic, dense and readable.
7. **Verdict** — confidence %, the one thing that would flip it, revise-up trigger.
8. **Links** — ledger grade · related close-ups · position on the north-star map.

## 3. Organization — by the north-star spine (not by date)
- **ĀYAH (unit):** "The Āyah, defined" [DEFINED] · "Inter-Āyah order" [REDUCES-TO-KNOWN, frozen binomials g65].
- **SŪRA (unit):** *(coming — same frame)*.
- **ARRANGEMENT:** "Inter-Sūra coherence" [REFUTED-ARTIFACT g30] · "Muṣḥaf vs revelation" *(folds in here)*.
Plus an **index/map page**: the north-star territory with each close-up placed + the journey line.

## 4. Signature visual = the gating cascade (reused everywhere)
A horizontal cascade: each gate a bar/step (random → length → period → size → nonlinear/split …), value = effect or
z, colored by survive/collapse, terminating in the badge. Honest + dense + illustrative; one literacy for all.
Examples already in hand: inter-Sūra 11→3.4→9.8→5.8→−0.7 (REFUTED); āyah = converging necessary conditions (DEFINED).

## 5. Dynamic / living (matches "we are evolving")
Close-ups are versioned. Status can CHANGE as instruments improve (REFUTED→revived; CANDIDATE→DISCOVERY). Each
carries a **status history** + a **revise-up trigger**, so the module visibly evolves rather than freezing. The
graded ledger is the data source; the close-up is its narrated, charted face.

## 6. Build order (recommended)
Seed the SYSTEM with the two exemplars that span the status range, proving the schema across its poles:
1. **Āyah — DEFINED** (the positive milestone) and **Inter-Sūra — REFUTED-ARTIFACT** (the cautionary method).
2. Then **Sūra** drops into the same frame as the next unit program.
Component reuse: one cascade chart, one badge component, one Arabic-exhibit block, one schema → every page.

## Ranked recommendation
1. **#1 — Build the SYSTEM (group + index/map + schema + status badges + reusable cascade chart), seeded with the
   two pole exemplars (Āyah DEFINED, Inter-Sūra REFUTED).** Scalable, honest-by-construction, future-proof; Sūra
   and all later close-ups inherit it for free.
2. **#2 — One page first (Inter-Sūra), schema retrofitted later** — faster, but invites rework and weaker honesty
   guarantees.
3. **#3 — Design only, build on the next go.**

Recommend **#1**.
