## Rules (LOCKED)
1. **Proof bar:** an attribute is PROVEN only with a clear indicator + a *proper* null (text's own shuffle or an
   arbitrary-segment control — never "chance" or a weak null) + a significant effect (z/t>2) with the **honest
   effect size stated** + a reproducible script.
2. **Correspondence / telescope principle:** the Qur'ān is assumed designed, so every property proven for a
   designed system HAS a correspondence here; a failed test indicts the **instrument**, not the text — refine,
   never file "disproven."
3. **احسن تقویم stance:** accept the design as optimal; characterize *how* it works; never test whether an
   alternative configuration would be "better."
4. **One at a time:** grow the catalog freely, but prove attributes in order, one fully before the next.
